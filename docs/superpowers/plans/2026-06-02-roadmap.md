# Block Collapser v1.0 — Implementation Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each phase plan. Phase plans use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Block Collapser v1.0 — a free WordPress plugin that adds editor-only collapse/expand to every block in the Gutenberg canvas — to the WordPress.org plugin directory.

**Architecture:** Single PHP bootstrap registers JS/CSS assets via `enqueue_block_editor_assets` so they reach the iframed editor. The JS layer hooks `editor.BlockListBlock` with a higher-order component that adds a chevron toggle and a 40px label bar. A `@wordpress/data` store holds the collapsed-block map, persisted to `localStorage` keyed by a stable structural path (`"0.2.1"`) or user-set `metadata.name`. A `PluginSidebar` exposes Collapse All / Expand All / Focus Mode. A settings React app at `Settings → Block Collapser` is backed by `register_setting` with REST exposure.

**Tech Stack:** PHP 7.4+ · WordPress 6.5+ · `@wordpress/scripts` (webpack) · `@wordpress/data`, `@wordpress/components`, `@wordpress/icons`, `@wordpress/keyboard-shortcuts`, `@wordpress/plugins`, `@wordpress/hooks` · PHPStan 1.x + `szepeviktor/phpstan-wordpress` · PHPCS + WPCS · ESLint (`@wordpress/eslint-plugin`).

**Source PRD:** `E:\projects\block-collapser\block-collapser-prd.docx` (v1.0, June 2026, Moaz Mahmoud).

## Cross-cutting decisions (locked, do not revisit without explicit user signoff)

1. **Persistence identity scheme:** Structural path + `metadata.name` fallback.
   State shape:
   ```json
   {
     "post:142": {
       "0": true,
       "3.1": true,
       "name:hero-cta": true
     }
   }
   ```
   Keys are tree paths (`"0.2.1"` = root[0].inner[2].inner[1]) unless the block has a user-set `metadata.name`, in which case `"name:<name>"` is used. Stable across reorder when name is set; degrades gracefully otherwise.

2. **Toolbar UX:** Single `PluginSidebar` panel titled "Block Collapser" with three actions inside (Collapse All / Expand All / Focus Mode). Works identically in Post Editor and Site Editor. No experimental SlotFills.

3. **State management:** `@wordpress/data` only (`createReduxStore` + `register`). No Zustand. Selectors return narrow `bool` per `clientId` and are memoized.

4. **CSS injection:** Editor styles enqueued via `enqueue_block_editor_assets` so they reach the iframed editor (WP 6.5+).

5. **Block-instance toolbar entry:** `BlockSettingsMenuControls` SlotFill for the "Never collapse this block" option, *not* a custom context menu.

6. **Keyboard shortcuts:** `@wordpress/keyboard-shortcuts` (`registerShortcut` + `useShortcut`). Default: `Alt+Shift+C` for Collapse All / Expand All toggle. Discoverable via WP's shortcut help modal.

7. **Animations:** Honor `prefers-reduced-motion: reduce` — fall back to instant transitions when set.

8. **Auto-draft posts:** When `postId === 0` (new unsaved post), persistence layer holds state in memory only. On first save, the in-memory state migrates to `localStorage` under the new post key.

9. **Synced patterns:** Treat each synced pattern as a single collapsible unit. Do not recurse into the pattern's inner blocks.

10. **Error boundary:** React error boundary wraps the HOC's wrapper output so a buggy third-party block can't crash the canvas through Block Collapser.

11. **Telemetry:** None. No phone-home. No external requests of any kind.

12. **i18n:** `Text Domain: block-collapser`, `__()` for all user-facing strings, `wp_set_script_translations` for JS strings, `load_plugin_textdomain` on `init`.

13. **Browser support:** Chrome 90+, Firefox 88+, Safari 14+, Edge 90+ (matches PRD §7).

14. **Min versions:** WordPress 6.5+, PHP 7.4+. (The PRD's "Interactivity API" justification for 6.5 is replaced with: iframed editor stability + modern SlotFills + `@wordpress/keyboard-shortcuts` stability.)

## Verification gates between phases

Before marking a phase complete, all of these must hold:

- `npm run build` succeeds with zero warnings
- `npm run lint:js` passes
- `npm run lint:css` passes (when stylelint added — Phase 1+)
- `composer run phpstan` reports 0 errors at the configured level
- `composer run phpcs` reports 0 violations
- Phase-specific tests pass (`npm test` for JS unit, `composer test` for PHPUnit when relevant)
- Manual smoke test in the live WP install at `wp-content/plugins/block-collapser/` succeeds — activate plugin, no PHP notices, no JS console errors, the phase's user-facing behavior works

Each phase plan ends with a final "Phase verification" task that explicitly walks through these gates.
